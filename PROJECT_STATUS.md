# VIBEX test7 upgrade — work in progress

Baseline: test7 source commit b048c1c. UI source was not intentionally modified. This is not a completed or release-ready upgrade.

## Progress and verification
- Web build and Capacitor Android sync succeeded. Android `assembleDebug` succeeded using JDK 21, one Gradle worker, and in-process Kotlin compilation.
- Android JVM unit suite: 42 tests passed, including three new tests for metadata matching, FLAC STREAMINFO parsing, and full-URL-derived cache keys. These are not playback or network security tests.
- Live Lossless search for Blinding Lights returned matching metadata; stream response identified FLAC, and a 42-byte HTTPS range response returned HTTP 206 and a FLAC marker. This is a single live contract/header check, not decoder or Android output evidence.
- DownloadManager's prior download resolver/cache layering has been restored. Playback streaming keys use a SHA-256 of the full resolved URL, rather than song ID or hostname. This is a proposed mitigation, not proof of download/offline correctness; end-to-end tests are still needed.
- A probe timeout can retain a candidate as unverified instead of asserting FLAC; malformed FLAC headers are still rejected. Diagnostics for other provider and decoder states are incomplete.
- No Android device was available; no on-device playback, background, focus, headset, download, or upgrade tests were performed.

## Release blockers
- Test download/offline compatibility and cross-source cache isolation end to end, including partial downloads and recovery. Review implications of signed URL rotation on cache reuse.
- Harden and test playback redirects and network security; the HTTP playback stack still follows ordinary same-protocol redirects and must not be assumed to enforce the adapter's host allowlist across redirects.
- Validate cancellation, bounded total resolution time and concurrency; the current synchronous resolver performs multiple network calls and should not be considered fully cancellable.
- Complete evidence states and reliable diagnostics, including decoder-confirmed evidence; improve matching only with recording-identity regression tests and verify contract variations. Some probe failure modes still reject unverified streams.
- Verify the complete JioSaavn in-process search, album, artist, playlist, metadata and playback paths and remove any hosted VIBEX backend dependence where required.
- Add security, redirect, range, MIME, expiry, codec, interruption, fallback, download, and lifecycle tests; verify actual device playback. Review package identity, signing, dependencies and licenses before distribution.
- The experimental debug APK uses a separate application ID `dev.viswesh.vibex.experimental`, so it installs separately from test7 and does not share its app data. It uses the public testing key and is not a production release.
- Preserve the exact test7 UI and existing features; get approval before any necessary UI change.

The build is an experimental intermediate, not the requested finished APK. A build success is not a quality or safety sign-off.

## FLAC download preview
VersionCode 15: previously DownloadManager always used the separate compressed downloadQuality and audio/mp4, even when a FLAC track was playing. New downloads in Auto/FLAC mode try a confirmed FLAC first; a currently selected FLAC or FLAC-only download setting requires FLAC and refuses an unverified compressed substitute.
