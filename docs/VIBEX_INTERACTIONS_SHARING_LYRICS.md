# VIBEX interactions, sharing and lyrics — implementation record

## Inspected baseline
The working project is `/home/user/vibex-performance`, reconstructed from the selected pre-Canvas experimental test7 build. `music-app/src/v2/` contains React screens, `Model.jsx` contexts and playback bridge, `ui.jsx` reusable track rows, artwork and `Sheet`, `Dialogs.jsx` song/playlist actions, `Player.jsx` queue, player and lyrics, `lyrics.js` provider chain, and `lib/lrc.js` parsing. Android is a Capacitor shell with the existing Media3 audio service and `VibexAudioPlugin`.

Current track menus use explicit more buttons and an existing accessible `Sheet`/`useModal`. Lyrics already support LRCLIB exact/search and KuGou, local/manual imports, synced and static results, timestamped word rendering where supplied, cancellation via AbortController, seek-to-line, and player-position-driven current-line scrolling. Existing activity manifest has a non-exported FileProvider; no existing song-card Android share implementation was found in the inspected paths. No production mock provider is appropriate.

## Planned implementation
- Add a reusable pointer long-press controller with motion cancellation, click suppression, context-menu and keyboard alternatives, attached to existing music elements. Preserve input/lyrics selection and existing action services and sheets.
- Extend existing song sheet using current queue, playlists, navigation and like state. Add relevant entity actions using existing navigation where verified. Keep bottom-sheet design and accessibility behavior.
- Generate original branded portrait/square images with bounded canvas size and robust fallback artwork; perform work asynchronously, reuse cached native artwork when possible. Ordinary sharing uses Android Sharesheet via a scoped cache FileProvider and temporary read permission, not a fabricated Snapchat intent. Lyric attribution/rights must be addressed before including provider lyrics.
- Improve existing lyrics behavior instead of replacing providers: efficient timestamp selection, user-controlled follow mode and return-to-current. Word highlighting must use only supplied timestamps and actual player snapshots.

## Files/modules and dependencies
Expected changes: `ui.jsx`, `Dialogs.jsx`, `App.jsx`, `Player.jsx`, `theme.css`, existing native bridge/manifest file-path resources, plus focused interaction, share and lyric utilities and tests. Prefer existing React/Capacitor/Media3 dependencies; only add dependencies after confirming necessity. Canvas artwork is deferred and not active in this selected baseline. No account/API key required for ordinary Android Sharesheet.

## Performance and safety
Do not block audio or the UI thread with provider calls or image decoding. Limit image dimensions and cleanup temporary files. Respect lyrics provider rights and avoid rendering unsupported or invented data. Keep cache access scoped and don't accept arbitrary file paths. Ensure gesture cancellation on movement/unmount and preserve form selection.

Run existing and new unit/browser tests, web build and Android debug build. Test song/entity long press, tap/scroll suppression, keyboard/menu, line/word/static lyrics, seeking, follow-mode behavior and share layout with local test-only fixtures. Device verification is required for Android Sharesheet/content grants, app-specific Snapchat behavior, haptics, touch, FLAC, background lifecycle and real-world performance. ## Initial limitations
No Android device is currently attached; no authorized Canvas provider is active. Snapchat direct integration will not be claimed without testing. Lyrics sharing depends on rights/attribution, not merely a provider response. Tooling and final build results will be recorded below.

## Implementation and verification — 2026-11-11

This is an **experimental partial implementation**, not a completed acceptance of all requested behavior. No Canvas was reintroduced. No third-party GPL source was copied, new service/provider or dependency added.

### What changed
- `long-press.js`, `LongPressButton.jsx` implement a 550 ms pointer gesture, movement/cancel/unmount cleanup, one-click suppression, native context-menu and Shift+F10/Menu key handling. Optional vibration uses the WebView/browser API where supported. `ui.jsx` applies it to song rows; Home/Search album/artist/playlist results and library playlist tiles use it too. Existing song sheet supplies queue/like/playlist/download/radio actions. Collection sheets currently only open the collection; they do not yet provide complete entity-specific action sets or a visible accessible menu button for every tile. Touch scrolling on a stationary pointer, long-press followed by component unmount and all device-specific context menu paths need further testing. Selection styling is scoped to music controls; lyrics remain selectable.
- `Dialogs.jsx`, `native.js`, `MainActivity.java`, `share/VibexSharePlugin.java`, `share/ShareFileProvider.java`, manifest and `share_card_paths.xml`: native-only song share actions generate 1080×1920 or 1080×1080 PNG on a worker. Branded gradient, bounded image decoding, rounded artwork fallback, and Android text layout are used. Artwork retrieval is limited to allowed HTTPS artwork hosts using existing VibeArtwork; missing, local or unsupported artwork gets a colored placeholder. Dedicated non-exported provider exposes only cache/share-cards, using an ACTION_SEND chooser with temporary read permission. Files older than 24 hours are cleaned on subsequent generation, not immediately after receipt. Existing broader export provider remains unchanged. Text may be ellipsized. This has not been visually verified on Android, for international shaping, or receiving apps. No specialized Snapchat integration is implemented. Current UI does not expose a lyric on cards; external lyrics rights/attribution remain unresolved. Do not infer a license from provider availability. The bridge has an unused manual text parameter; no UI sends it and no attribution implementation exists.
- `Player.jsx`, `lyrics-timing.js`: binary search for existing sorted supplied timestamps, existing actual playback state and offset, current-line-only word highlight, user touch/wheel disables automatic scroll with a return button, and resets follow on track change. Existing LRCLIB/KuGou/manual sources, matching, abort, line seeking and static display remain. No interpolated/fabricated word timings were introduced. Mouse scrollbar/keyboard scrolling does not explicitly suspend follow; screen-reader and WebView behavior require device testing.
- Other changed files: `App.jsx`, `HomeView.jsx`, `SearchView.jsx`, `LibraryView.jsx`, `theme.css`; focused tests `long-press.test.mjs` and `lyrics-timing.test.mjs`; Android version code 20. No repository `.git` exists; manually inspected changed source paths and generated resources, no commit or merge.
